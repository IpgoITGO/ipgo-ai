# 0007. DA07 최소20건·HTTP/SQS 표본 공급

## 2026-11-13 후속: DA-07 상품별 주기와 요청 계산량 (#111)

engineVersion **0.6.1**부터 16,000회 한도를 넘는 요청도 수량·재고 계산을 계속한다.
아래 최초 구현의 계산량 초과 HTTP422/SQS FAILED 설명은 이 변경 이전의 이력이다.

- H=리드타임+입고 주기, D=오늘과 기준일 차이+H를 모으고 길이별 비용을
  조정 구간 전체 SKU 수×성숙한 주간 기준일 수×A/B2회로 계산한다.
- 현재 품절 위험용 D를 우선한다. 같은 우선순위에서는 비용·길이 오름차순으로
  완전한 묶음을 선택해 합계를 16,000회 이하로 유지한다. 요청/원본 상품 순서와 무관하다.
  들어오지 않는 길이를 건너뛰고 남은 예산에 들어오는 다른 길이는 계속 평가한다.
- 한 길이의 SKU pool이나 기준일 일부를 자르지 않고 서로 다른 길이를 합치지 않는다.
  선택된 묶음의 산식·비율·표본 수·관측 확정일·정책 hash는 기존과 같다.
  주간 기준일·최소20건 정책과 정책 파일은 변경하지 않는다.
- 보류한 D의 riskStatus/riskSampleSize/riskBasis/preArrivalRisk와 시나리오 위험은
  기존 미산출 계약인 null이다. insightInput도 null이며 INSUFFICIENT_SAMPLE이나 0%로 만들지 않는다.
  보류한 H는 accuracyEvaluation.status=UNAVAILABLE,
  reason=EVALUATION_CAPACITY_EXCEEDED, 빈 history로 구별한다. 공개 필드나 enum은 추가하지 않는다.
  비용 때문에 보류한 길이는 요청 내부 RiskContext.unavailable_horizons로만 전달한다.
- HTTP·SQS·직접 입력 시나리오가 같은 처리를 쓴다. 잘못된 원본·날짜·정책과
  다른 서비스 용량 제한의 오류는 그대로 유지한다. 예외 전체를 잡아 성공으로 바꾸지 않는다.

합성 185상품·H16/20/88·D19/23/91·주간45기준일 합계는 16,650회다.
D를 모두 유지하고 H20만 보류하면 12,580회이며, 세 상품의 품절 위험도 계산할 수 있다.
이는 이슈의 차원·비용을 재현한 로컬 합성 회귀이며 실제 계정 데이터·배포 후 성공 근거가 아니다.
추가로 정확한 상한·모든 묶음 초과·HTTP/SQS/CUSTOM·수량/재고 보존을 검증한다.
실제 고객 화면·실DB·최대부하와 배포 후 검증은 수행하지 않는다. 코드 복구는 #111 PR revert이며
운영 배포를 수행하기 전에는 서비스 복구 조작이 없다.

## 최초 구현 기록

- 상태: 2026-11-03 사용자 위임에 따른 로컬 구현·검증. 배포 완료는 별도다.
- [0006](0006-da07-stockout-risk.md)의 최소 기준/공급 경로 미완료 항목을 이 범위에서 갱신한다.
- 근거: 사용자가 제공한 비공개 원장의5~7월 조정 자료, 기존 DA01/02/08/07 규칙과 원본 요구사항,
  후보 비교를 보여준 뒤 받은 “너가 권장하는대로”라는 운영 기준 선택 위임.
  원본·상품명·바코드·원가·상품별 값은 저장소에 넣지 않는다.

## 기준과 선택 이유

최소 표본 수는 **20건**, 조정 기간은2026-05-01~07-31, 기준일은5/1부터7일 간격이다.
마지막 후보 기준일은7/24이며 종료일이7/31을 넘는 창은 사용하지 않는다.
정책은 `app/risk_policy_2026.json`의 `da07-2026-tune-weekly-v1`로 고정한다.
실제 결정일2026-11-03을 availableOn에 넣어 과거 시점에 이미 결정된 정책처럼 소급하지 않는다.

20건은 한 사건의 빈도 분해능100/N을5%p 이내로 두는 운영 문턱이다.
5건/10건의20%p/10%p보다 거친 빈도 표시를 줄이는 선택이며, 실제 자료에서 pooled 표본이 충분함을 확인했다.
데이터가20건의 통계적 최적성·95% 신뢰도·위험 보정을 입증했다는 뜻은 아니다.
겹치는 창과 SKU 간 상관은 그대로 남는다. 실제 품절 위험 보정은 DA10에서 별도로 검증한다.

비공개 원장 파생 자료의 주간 평가 결과는 다음과 같다. 산식·길이를 섞지 않았고8~9월 TEST를 쓰지 않았다.

| 예측 길이 D | 산식 | 유효 비율 사례 | 상품별 최대 사례 |
|---|---|---|---|
| 10일 | A | 312 | 12 |
| 10일 | B | 758 | 12 |
| 34일 | A | 338 | 9 |
| 34일 | B | 561 | 9 |

이번 주간 평가 자료에서는 최소20건을 만족하는 SKU가 없어 모두 POOLED가 된다.
다른 데이터에서도 SKU별20건 이상이면 SKU 우선, pooled도 미만이면 INSUFFICIENT_SAMPLE이다.
이 표는 D10/34의 표본 가용성 조사이며 모든 D의 신뢰도 검증이나 실제 사용자 흐름 성공이 아니다.
최소 기준과 기준일을 바꾸는 것은 정책 변경이므로 버전·근거를 함께 바꾼다.

## 실제 자료 검사 범위

- 원본을 변경하지 않고2025/2026년2~7월12개 파일을 별도 오프라인 프로세스에서 정제·월 경계 검산했다.
  이 범위의 검산 불일치는0건이다. 각 연도 첫2월의 기초는 기존 DA01 첫날 역산 규칙을 따랐다.
- 현재 서비스의 정제 격자 상한을 원본이 초과한다. **오프라인 프로세스만** 조사 상한을 확장해
  파생 자료를 만들었으며 원래 서비스 코드/제한은 보존했다. 최초 거절과 후속 분석은 다른 증거다.
- 2025년1월은 입고일 전 비영 수량이 있는 기록이 감지돼 이번 계산에서 제외했다.
  혼적제한단위·월별 집계 자료를 재고관리단위 일별 자료와 합산하지 않았다.
- 원장 전체 업로드 수용, 미관측 수요 복원·실제 수요 정확도, 실제DB/고객 E2E는 이번 분석 결과가 아니다.

## 공통 계산 경로

1. 기존 HTTP/SQS 경로가 단일 읽기 전용 DB 연결에서 회원·창고·업로드DONE 소유권을 확인한다.
2. 두 경로와 직접 입력 시나리오는 `app.calculation`을 공유한다. 같은 DataFrame의 요청 uploadFileIds와
   기준일 이하 자료만 표본·계산에 사용하며 다른 source를 자동 조회하거나 cache로 섞지 않는다.
3. 고정 정책을 읽고 request.today가 availableOn 이전이면 위험을 보류한다.
   이는 현재 결정한 정책을 과거 백테스트에 미리 알려진 것으로 적용하지 않기 위함이다.
4. 요청한 상품 설정별 **D=g+H**를 고유하게 모아 DA08의 A/B 표본을 생성한다.
   pool은 productIds에 제한하지 않고 같은 source의 조정 구간 상품 전체를 쓴다.
   조정 구간에 실적 행이 전혀 없는 과거 전용 SKU는 유효 비율을 만들 수 없어 작업 대상에서 제외한다.
5. 표본 종료일은 조정 종료일과 현재 계산 기준일 이내다. 원본에 미래 행이 있어도 예측/평가에 쓰지 않는다.
   산식·D·TUNE별로 분리한 context를 기존 calculate/custom_scenario에 전달한다.
6. 기존 SKU/POOLED/부족·LOW 억제와 입력 변환을 실행한다. 수량/기본 시나리오·NO_DATE 규칙은 그대로다.

원본의 소유권 실패는 기존 오류 경로를 유지한다. 표본 구조/계산 오류와 계산량 초과는 HTTP422·SQS FAILED/INVALID_INPUT,
정책 파일/해시 손상은 HTTP503/RISK_POLICY_INVALID와 기존 worker 재시도 경로다.
파일 경로·내부 예외·원본 값은 응답/로그에 넣지 않는다.

## 버전·비활성·용량

- 공개 JSON 필드를 추가하지 않는다. 정책/계산 결과가 바뀌므로 real engineVersion은 **0.5.0**이다.
  고정 정책 파일은 앱 image에 들어가고 SHA256을 코드에서 대조한다. 외부 파일 override는 지원하지 않는다.
  재현 시 input snapshot·source와 함께 해당 engineVersion/image를 보존한다.
- IPGO_RISK_ENABLED는 기본true이고 false이면 명시적으로 위험을 보류해 null을 반환한다.
  비활성을 허위 표본 부족이나 위험0으로 바꾸지 않는다. 실제 환경은 이번에 변경하지 않았다.
- 요청당 표본 예측 후보는 조정 구간 SKU수×성숙한 기준일수×A/B2개를 D별 합산해 최대8,000개다.
  통계적 최소 표본 기준과 구별되는 서비스 계산량 보호 한도다. 재고 시나리오·원본 조회의 기존 상한도 유지한다.
- 실제 파생 자료의 두 길이 후보 조사(7,770개 예측 후보)는 로컬27.563초/child maxRSS104,096KiB였다.
  이는 오프라인 조사이며 HTTP 전체 시간이나256MiB/ARM/최대 입력 보장이 아니다.
- 별도256MiB x86 컨테이너·네트워크 차단의 단일 합성31상품 SQS 공통 경로가3.736초,
  cgroup peak138,452,992바이트·OOM0으로 통과했다. 실제 고객 자료·동시 부하·ARM 결과와 구분한다.

## 조사 재현과 남은 범위

`scripts/audit-risk-samples.py`는 비공개 정제 product_daily CSV와 명시한 기간/일수/후보로 집계한다.
최대16MiB/100,000행인 오프라인 입력만 읽고 저장소 밖 새0600 JSON에 원본 해시·집계·제외 사유를 남긴다.
상품 식별자/원본 값은 출력하지 않고 기존 파일을 덮어쓰지 않는다. selected_min_samples는 자동 채택하지 않아None이다.
20건 채택은 위 데이터 확인 후 사용자 위임으로 결정한 별도 정책이며 도구가 최적값을 발견한 것으로 기록하지 않는다.

이번에는 원본 업로드 제한·2025년1월 오류를 수정하거나 DB 원본을 다시 적재하지 않았다.
DA13 전체등급/LOW범위·전체 백테스트/정책 선정·DA10 신뢰도·Spring 저장/실제 고객 검증은 별도다.
LLM·prompt·키·배포 설정을 변경하거나 실제 LLM을 호출하지 않는다.
