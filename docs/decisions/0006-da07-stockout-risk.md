## 원문에 확정된 규칙과 미확정 값

- 조정 기준일은 5~7월이며 평가 종료일이 7/31 이내인 표본을 쓴다. TEST 결과를 위험 분포에 섞지 않는다.
- 비율은 유효일 실제 출고 합 / 같은 날 예상 출고 합이다. 예측0은 제외한다.
- 같은 비율을 기준일 t 이후 오늘 s까지의 g일 예측과 s+1~s+H일 시나리오에 함께 적용한다.
- 도착 전 위험은 공통, 도착 후 위험은 시나리오별로 표시한다. 사건은 미충족 수요 발생이며 기말0과 다르다.
- SKU 표본이 부족하면 전체 SKU 비율을 사용한다. 전체도 부족하면 미산출한다.
- 유효 관측일 7~13일은 LOW_GRADE로 위험을 억제한다. DA13 전체 등급·LOW 출고 범위는 이 작업에서 정하지 않는다.
- **최소 표본 수는 원문에도 5~7월 자료로 결정할 미확정 값이다.** 기본값을 넣지 않는다.
  기준일 간격·추세 경계·정책 고정/저장도 이번 구현이 확정하지 않는다.

## 선택 계약

`RiskContext(batches, period_start, period_end, min_samples)`는 DA08 batch tuple과 조정 연도의
5/1~7/31, 양의 정수 최소 표본 수를 명시한다. 이는 공개 HTTP/SQS schema에 추가한 필드가 아니다.
같은 회원·창고·승인된 source를 읽은 batch만 전달하는 것은 호출자 책임이다. DA08 batch 자체에는
회원·창고·업로드 식별자가 없으므로 이 함수로 소유권을 검증했다고 보고하지 않는다.

`select_risk_samples(context, product_id, method, horizon_days, observed_through)`는 다음을 적용한다.

1. 같은 TUNE 기간·실제 사용한 산식(A/B)·예측 길이의 표본만 선택한다. 기본 산식이 실패했으면
   실제 대체 산식의 표본을 사용하며 A/B를 섞지 않는다.
2. 예측 길이는 현재 계산의 **D=g+H**다. g>0인 예측에 H일 표본을 대신 쓰지 않는다.
   이는 같은 길이의 오차를 재적용하기 위한 내부 선택 규칙이다. 다른 길이 통합은 별도 검증 전에는 하지 않는다.
3. 표본 종료일은 조정 종료일·batch 관측 확정일·현재 계산 기준일 모두 이내여야 한다.
   나중에 생성한 batch라도 당시 아직 모르는 실적은 쓰지 않는다.
4. 예측0/비유한 비율은 제외 사유를 보존한다. 실제 출고0/양수 예측의 비율0은 유효하다.
   모순된 수량·비율·중복 표본은 RiskInputError다. 이를 표본 부족으로 바꾸지 않는다.
5. SKU 표본 수가 최소 기준 이상이면 SKU만 선택한다. 미만이면 같은 조건의 **대상 SKU 포함 전체 SKU**를
   pooled로 선택한다. 전체도 미만이면 basis=None과 실제 후보 표본 수를 반환한다.

표본은 상품 ID·기준일 순으로 고정한다. 동일 창의 중복 공급은 오류이며, 서로 겹치는 평가 창은
다른 평가 사례로 유지한다. 반환 수는 사용 가능한 오차 사례 수이며 독립 표본 수/통계적 신뢰도가 아니다.
현재 DA08 최소 생성기는 평가 창 전체 날짜가 유효한 경우만 만든다. 일부 유효일만 있는 창을 활용하는
확장은 아직 없으며, 보수적인 제외로 표본 수와 대표성이 제한될 수 있다.

## 재적용 식과 반환

`engine.scenario.stockout_risk()`는 선택된 비율 tuple과 실제 재고·일평균 예측·g/H/L·신규 입고량·
g일 기존 발주·H일 기존 발주를 받는다. 과거의 2인자 stub에는 이 입력이 없어 실제 계산이 불가능했으며,
새 keyword 인자는 내부 계약이다. 기존 호출자는 없고 공개 JSON schema는 바꾸지 않는다.

각 표본 r에 대해 다음을 수행한다(수량 개, 일평균 개/일, 비율 무차원).

1. 일평균 출고를 d×r로 만든다. 배수는 권장 입고량 산정에만 쓰며 예상 출고에 재적용하지 않는다.
2. 기준일 실제 기말 재고에서 출발해 g일을 날짜별로 재생한다. 그날 기존 발주를 더하고 d×r을 빼며
   매일 재고를0 이상으로 제한한다. g일의 판매 손실을 오늘 이후로 넘기지 않는다.
3. 재생한 시작 재고에서 기존 DA06 simulate를 실행한다. 신규/기존 입고 수량·도착일은 고정하고
   입고 후 출고, 미충족 비이월 규칙을 그대로 쓴다. 표본마다 권장량을 다시 계산하지 않는다.
4. pre = 도착 전(s+1~s+L−1)에 미충족이 생긴 사례 수 / N,
   post = 도착 후(s+L~s+H)에 미충족이 생긴 사례 수 / N이다. 조건부 확률이 아닌 각각의 경험 비율이다.
   g일의 부족은 시작 재고에만 반영한다. L=1의 도착 전 빈 구간은 표본이 충분할 때 위험0이다.

비율을 자르거나 재고/위험을 화면 단위로 반올림하지 않는다. 날짜 없는 발주는 계산에 넣지 않는다.
부족한 표본은 위험 None과 실제 표본 수, 잘못된 입력·비유한 재적용은 오류다.

## 계산 연결과 비활성 경계

- `calculate(..., risk_context=...)`와 `custom_scenario(..., risk_context=...)`에 선택적으로 연결한다.
  기존 수량·시나리오 재고·소진일·미충족 값은 바꾸지 않는다.
- 준비된 context가 있으면 OK / INSUFFICIENT_SAMPLE / LOW_GRADE와 실제 사용 가능한 표본 수를 채운다.
  basis는 실제 위험을 산출한 경우만 SKU/POOLED다. LOW_GRADE는 표본이 충분해도 모든 위험이 None이다.
- 이후 기존 입력 변환기를 사용한다. LOW 범위 미완성은 insightInput=None이며 값을 만들지 않는다.
  NOT_NEEDED는 기존 빈 시나리오·인사이트 미호출 규칙을 유지하고, 직접 입력 시나리오는 같은 context를 쓴다.
- context를 공급하지 않으면 riskStatus/위험/표본/기준은 기존 null이다. 정책 미확정을
  INSUFFICIENT_SAMPLE 또는 위험0으로 숨기지 않는다.
- HTTP/SQS/DB 공급 경로는 아직 context를 만들지 않는다. 운영 적용에는 원본 자료에서 최소 기준·기준일을
  정한 뒤 동일 source의 산식·D별 DA08 batch를 생성/고정/공급하는 후속 연결이 필요하다.
- LLM 호출·prompt·환경 변수·서버·배포는 변경하지 않는다. 내부 계산이 insightInput을 반환해도 LLM을 호출하지 않는다.

## 검증과 한계

- 기존 사람이 작성한 DA06의 도착 전/후 사건을 비율1로 재생하고, 비율0 혼합·빈도 불변·입고량 단조성·
  도착 전 공통성·기말0/미충족 구분·g일 재생·입고일 경계를 검증한다.
- TUNE/TEST·다른 기간/산식/D·관측 확정일·0 분모·표본 부족·중복/모순·SKU/POOLED 선택과
  DA08 실제 생성→계산→insightInput 변환을 로컬 합성 데이터로 검증한다.
- AI가 새 DA07 손계산 fixture를 사람 검산 완료로 표시하지 않는다. DA10의 실제 위험 구간 보정·대표성,
  최소 표본 수의 적정성·전체 백테스트·실제 고객 흐름·운영 성능·LLM 효과는 이 테스트로 입증하지 않는다.
