# DA-01 정제 날짜의 업로드 기간 사용 (#123)

개발 환경에서 Server가 입고일자로 확정한 월을 DB에 저장한 뒤에도 AI가 파일명 연월을 다시 요구해
임의 파일명 업로드가 실패했다. 정제의 날짜 열은 일자만 있으므로 검증된 업로드 기간의 연월을 사용한다.

`load_cleaning_context`는 DB에서 업로드·사용자·창고·storage key·원본명·PROCESSING 상태를 대조한 뒤
기간을 반환한다. 이 값을 기존 `clean(period=...)`에서 `read_ledger`까지 전달한다.
요청 schema나 DB view·원본 파일명은 변경하지 않는다. 파일명 연월이 있다면 기간과 일치해야 하며,
복수 연월과 여러 월에 걸친 기간은 거절한다. 생성된 날짜가 기간 밖이면 기존 검사에서 거절한다.
DB 없이 호출하는 기존 함수 사용자는 파일명 연월을 계속 제공한다.

HTTP와 worker의 공통 정제 경로에 합성 XLSX 회귀 검사를 추가했다. 계산식·모델·데이터셋 영향은 없다.
배포 전까지는 실제 개발 환경의 실패가 해결된 것으로 판정하지 않는다.
